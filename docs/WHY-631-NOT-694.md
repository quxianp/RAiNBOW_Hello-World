# Why 694 core files but 631 segments on the bar

The single most common confusion about this repository. Here is the whole
argument, with the numbers.

## The claim

The repository contains **694** core files, one per Linguist-coloured and
detectable language. GitHub's language bar renders **631** segments.

Both numbers are correct. They measure different things.

## Why they differ

Linguist does not treat every language name as distinct. When several languages
are so closely related that Linguist classifies them as variants, it **merges
their bytes into the parent language's segment**.

The clearest example is the HTML family. The repository contains 7 files that
Linguist attributes to HTML:

```
hello/core/html/           hello/core/haml/
hello/core/handlebars/     hello/core/jinja/
hello/core/mustache/       hello/core/razor/
hello/core/erb/
```

Each is exactly 2048 bytes, like every other core file. GitHub does not draw 7
thin segments — it draws **one** segment that is 7 × 2048 bytes wide, and labels
it `HTML`.

That is the whole explanation, and you can check it in the numbers:

```
1 core file        = 1 / 694      = 0.144092 %
7 HTML-family files = 7 × 2048 B  = 1.0116 %   <- what the API reports
```

## This was measured, not assumed

Two independent pieces of evidence:

**1. `github-linguist` itself** (`scripts/linguist_audit.rb`, run in CI):

```
aggregate_language_count: 631
HTML:                    14336 bytes  (1.0116 %)
```

The API endpoint `GET /repos/quxianp/RAiNBOW_Hello-World/languages` returns
byte-identical figures: 631 languages, 1 417 216 bytes total, HTML at 1.0116 %.

**2. An A/B test on the modelines** (`scripts/modeline_ab_test.rb`):

| Variant | Languages reported | Files |
|---|---|---|
| A — with per-file modelines | 631 | 694 |
| B — modelines stripped | 631 | 694 |
| difference | **0** | 0 |

If the missing 63 were a detection failure caused by how the files are annotated,
stripping the modelines would change the count. It does not. The 63 are folded by
Linguist regardless of annotation.

> An earlier draft of this README claimed 64 files were "misclassified". That
> was derived from byte arithmetic alone and was **wrong**. It is retracted in
> `logs/ERRORS.log` as E17.

## Why the bar still looks complete

Because it is complete. 631 segments, each `0.144092 %` wide, is still 631
hair-thin coloured slivers sweeping through the full hue circle. Nothing is
missing from the *picture*; what is missing is the *labelling*.

## Why GitHub will never list them

The legend below the bar shows only the largest few languages, then a grey
**Other** row containing everything else. At 631 languages, "everything else" is
most of them — including C, C++, C# and Java, each only marginally larger than
its 693 neighbours.

No repository-side change can fix this. It is a property of the UI. Which is why
`assets/rainbow-bar-github.png` is **rendered** from the API rather than
screenshotted: it lists all 631 by name, with their real colours and shares, so
the information GitHub declines to display is still available.

## Can it be pushed to 694?

Only by getting Linguist to treat the folded dialects as distinct languages —
which is a change to Linguist, not to this repository. Until then 631 is the
ceiling, and the 694 core files remain the correct number of *languages in the
repository*.
